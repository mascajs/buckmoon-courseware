# Student worksheet workflow

Use this reference when a lesson asks students to search, collect data, discuss, calculate, interpret, record evidence, or prepare a presentation.

## Start from the lesson, not the old worksheet

Read the confirmed lesson script and deck outline first. Identify:

- what the class produces;
- which information the whole team shares;
- which thinking each student should do alone;
- what the team must decide together;
- what the teacher will collect or assess;
- where students are likely to stop because a prompt is unclear.

When an older worksheet is supplied, render and inspect every page. Record its useful structure, writing load, table logic, repeated fields, and design constraints. Then compare it with the new lesson. Reuse a field only when it supports the new activity. Treat the reference as evidence, not as a template by default.

## Choose the ownership mode

Use one of these modes or a deliberate combination:

- **individual**: each student collects and interprets separate evidence;
- **team-common**: the team records one shared data set and one shared conclusion;
- **shared-data / individual-observation**: the team shares one data set, but each student records a different observation;
- **individual-scan / team-one-finding**: each student first writes one short observation, then the team selects one finding to develop and present.

Do not create several answer boxes merely because the team has several members. If the final output is one team finding, use the short individual scan only to widen discussion, then provide one clearly larger team-answer field.

## Build the evidence chain

A data-based worksheet should normally preserve this evidence chain. Adapt or remove fields that the lesson does not use:

1. **source identity** — topic, source, collection conditions, units, variables, and file or artifact name;
2. **first look** — what changed, where it changed, and which point deserves attention;
3. **selection** — the one observation, question, or result the student or team will explain;
4. **observed evidence** — values, position, shape, sequence, quotation, or other detail read directly from the source;
5. **interpretation** — the relevant concept, variable, or relationship, stated with appropriate certainty;
6. **alternative explanation** — another event or condition that would require separate evidence;
7. **source or model limit** — what cannot be concluded from the available material;
8. **presentation or submission** — a short claim, evidence, limitation, and deliverable checklist.

Delete steps the lesson does not use. Add a field only when the teacher will use it during instruction, feedback, presentation, or assessment.

## Student wording

- Use the exact term taught in class, followed by a short plain-language cue when needed.
- Ask one action per prompt. Prefer `정점은 언제인가요?` to `상승·정점·하강의 특징을 종합해 보세요.`
- Provide a sentence starter when students must distinguish observation from interpretation.
- Mark examples as examples so students do not copy them as answers.
- Avoid vague fields such as `느낀 점`, `패턴`, `분석 결과`, or `한 줄 정리` unless the prompt says what evidence belongs there.
- Keep teacher tips, expected answers, timing, and intervention rules off the student worksheet. Put them in a separate teacher guide or speaker notes.

## Page and writing design

- Give the largest writing area to the most important student decision, not to names or decoration.
- Keep shared team information in one place. Do not ask students to rewrite the same search conditions on every page.
- Put prompts beside the space where students answer them.
- Use checkboxes for completion checks, not for explanations that need a sentence.
- Leave enough room for ordinary handwriting. Render at print size and inspect the actual writing areas.
- Prefer an editable source file. Use A4 portrait or landscape when the worksheet will be printed; use 16:9 only when the user wants a screen-first worksheet.

### Screen-first PowerPoint entry mode

When students will complete the worksheet in PowerPoint, optimize for one-click editing rather than for paper handwriting.

- Make each answer area a single, editable text box with its own fill and border. Do not place a non-editable rectangle behind a separate text box, and do not use underscore lines as the answer field.
- Put a short placeholder or clearly marked example inside the editable field, such as `여기에 입력하세요` or a one-sentence example that matches the expected answer type. Students should be able to click the visible field once and type.
- Use checkboxes only when students truly need to choose or confirm several items. A decorative `□` character is not an interactive control; replace it with a short input field or a plain submission list when checking is not essential.
- Keep the main team decision visually larger than individual warm-up notes. If several members write first, use compact one-line fields and reserve the largest field for the one answer the team will present.
- Do not ask students to copy a sentence onto the next slide merely to preserve continuity. Refer to the previous slide and use the space for the next thinking step.
- Test the delivered `.pptx` by clicking representative answer fields in PowerPoint or by inspecting the shape structure. Confirm that the answer text itself is directly editable and not grouped behind another object.

### Typography and space for a projected worksheet

Do not apply print-sized typography to a 16:9 worksheet that students will read on a classroom screen.

- Use the supplied or user-selected Korean font throughout the visible worksheet when the user has applied it beyond titles. Do not leave the body and editable fields in a fallback font merely because the title font is decorative or was first introduced as a heading font.
- Treat the following as a starting range for a screen-first wide worksheet, then adjust after rendering: main title about 28–32 pt, editable answer text about 14–16 pt, prompts and section labels about 12–14 pt, and 9–11 pt only for genuinely secondary notes. Readability from the back of the room takes priority over fitting another instruction line.
- Do not reserve a subtitle slot on every page. Remove the subtitle when it merely repeats the title or the first visible prompt; keep it only when it changes how students perform the task.
- Size each answer field for the expected answer, not for visual symmetry. A reason, limitation, or further-research sentence may need a taller field than a search term or role name.
- Avoid placing every section in an equal rounded card. Use cards for real grouping or emphasis. When the task order is already clear, typography, spacing, and one accent line can provide the hierarchy with less visual clutter.
- Give most of the canvas to the activity students must complete. A graph, shared team conclusion, or presentation sentence should dominate; warm-up notes, submission reminders, and optional work can be compact.
- When a sentence scaffold must support speaking, include the actual reasoning moves students need. For example, a limitation prompt may need separate blanks for the evidence, what cannot be confirmed, and how the team would investigate it, rather than one vague `모르는 점` blank.

### Learn from a user-edited worksheet

When the user edits a generated `.pptx`, treat that file as the authority for the current project.

1. Compare it with the last generated candidate before making another revision. Check font family and weight, type sizes, deleted copy, moved or resized shapes, answer-field height, container removal, and changes to sentence scaffolds.
2. Preserve the user's edits. Do not regenerate from an older source and accidentally restore removed copy, superseded layout decisions, or previous wording.
3. Separate two kinds of learning in the project record:
   - **project decisions**: the selected font, exact title scale, margins, colors, page-specific placement, and wording for this worksheet;
   - **reusable principles**: readable input text, no automatic subtitle, space based on answer length, restrained card use, and emphasis on the main student action.
4. Render every slide after the comparison. A structurally valid deck can still become crowded when font size increases or fields move toward the slide edge.

## Minimum worksheet plan

Before design, record for each page:

- purpose in the lesson;
- who writes: individual, one recorder, or every member;
- exact student prompts;
- expected answer length;
- information carried in from the previous page;
- teacher-only guidance that must stay out;
- submission or presentation use.

## QA

Ask a novice-student question for every field: `What exactly should I write here?` If the answer is not obvious from the printed page, rewrite the prompt or add a short example.

Also confirm:

- every field maps to a confirmed lesson action;
- individual and team answers are visually distinct;
- students record the source conditions needed to interpret the data;
- observation, model interpretation, and outside explanation are not merged into one box;
- optional tools or extension work are clearly optional and do not block the core path;
- the final presentation can be prepared from the worksheet without inventing missing evidence;
- no teacher tip, answer key, minute marker, or production note appears in the student artifact;
- text and writing lines remain usable after printing.

## Output discipline

Follow the single-output rule in the main skill. Finish field wording before the first artifact build, keep candidates and renders private, and publish only the validated canonical file unless the user requests preserved variants.
